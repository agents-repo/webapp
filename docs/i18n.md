# Internationalization (i18n)

This document describes how locale routing, translations, and SEO interact in
the webapp.

## Supported locales

| Locale | URL prefix | `html lang` | Notes |
| --- | --- | --- | --- |
| English (`en`) | _(none)_ | `en` | Default locale |
| Spanish (`es`) | `/es/` | `es` | Full shell + privacy policy |
| Portuguese Brazil (`pt-BR`) | `/pt-br/` | `pt-BR` | Full shell + privacy policy |
| Portuguese Portugal (`pt-PT`) | `/pt-pt/` | `pt-PT` | Full shell + privacy policy |

Locale definitions live in
`src/modules/site/application/i18n/supportedLocales.ts`.

## Core modules

| Path | Role |
| --- | --- |
| `i18n.ts` | i18next bootstrap (`shell`, `catalog`, `pages`, `docs` namespaces) |
| `LocaleProvider.tsx` | Syncs URL locale, `document.documentElement.lang`, and i18next |
| `localePath.ts` | Parse/strip locale prefixes; build localized paths |
| `useLocalizedSitePath.ts` | Hooks for locale-aware links and locale switching |
| `detectBrowserLocale.ts` | First-visit home redirect from `navigator.languages` |
| `googleTranslate.ts` | Optional Google Translate link on non-English catalog and package pages |

Translation JSON files live under `src/locales/<locale>/`.

## URL model

- English routes stay unprefixed (`/about/`, `/packages/`).
- Other locales prepend a slug (`/es/about/`, `/pt-br/privacy/`).
- `App.tsx` strips the locale segment before matching `react-router` routes.
- `LocaleProvider` wraps the app inside `BrowserRouter` in `main.tsx`.

Legacy `/privacidade` redirects to `/pt-br/privacy/`.

## Shell UI

Header, footer, cookie banner, and theme dropdown use the `shell` namespace.
`LocaleDropdown` in the header and footer language links call `useSwitchLocale`
to navigate to the same logical path in another locale.

## Privacy policy

A single `PrivacyPage` selects content by locale (`en`, `es`, `pt-BR`, `pt-PT`).
Language cross-links use `languageLinks` on each
`PrivacyPolicyContent` object.

## SEO and static HTML

- `getBuildSitemapPaths()` in `scripts/seo-build-config.ts` expands every build
  route across all locales for `vite-plugin-sitemap` and `prepare-pages-dist.mjs`.
- `SiteHead` and `buildRouteHead.ts` emit per-locale `og:locale` and `hreflang`
  alternates.
- `getSitePageMeta` and `getSiteSeoMeta` strip locale prefixes before route
  lookup; canonical URLs are localized.
